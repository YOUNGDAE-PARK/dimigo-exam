# Ⅱ. 데이터 (디미고 소질·적성검사 핵심 요약)

> **디미고 실전 출제 유형 4가지**:

> ④ **비트맵 vs 벡터, 아스키 vs 유니코드, 소리 디지털화 3단계 선지 판별**

## 1. 디지털 데이터 표현과 2진수 실전 계산

### 1.1 비트(Bit)·바이트(Byte)와 데이터 용량 단위 계층 (`2^n` 공식)

```
• 1 Bit (최소 단위) = [ 0 ] 또는 [ 1 ]  ──▶  2¹ = 2가지 표현
• n Bit (0과 1이 n자리)                 ──▶  2ⁿ가지 표현
• 1 Byte = 8 Bit 묶음                   ──▶  2⁸ = 256가지 표현 (영문·숫자 1글자 저장 기본 단위)

[데이터 용량 단위 크기 순서 (매 단계 2¹⁰ = 1,024배씩 증가)]
  Bit < Byte(8 bit) < KB(2¹⁰ B) < MB(2²⁰ B) < GB(2³⁰ B) < TB(2⁴⁰ B) < PB(2⁵⁰ B)
  (1 KB = 1,024 Byte | 1 MB = 1,024 KB | 1 GB = 1,024 MB | 1 TB = 1,024 GB)

[시험장 1초 암기표]
 2³ = 8  |  2⁴ = 16  |  2⁵ = 32  |  2⁶ = 64  |  2⁷ = 128  |  2⁸ = 256  |  2¹⁰ = 1,024
```
* **★ 실전 문제 공식 ("최소 몇 비트가 필요한가?" & "용량·전송시간 계산")**:
  * **최소 비트 수**: 구별해야 할 대상이 `N`가지일 때, **`2ⁿ ≥ N`을 만족하는 가장 작은 `n`**을 찾습니다. (예: 50종류 상품 구별 → `2⁵(32) < 50 ≤ 2⁶(64)` 이므로 **최소 6비트** 필요)
  * **네트워크 전송 시간 함정 (`Byte` vs `bps`)**: 파일 용량은 **`Byte`** 단위를 쓰고 전송 속도(`bps`)는 초당 **`Bit`** 수를 뜻하므로, 전송 시간을 구할 때는 **`파일 용량(Byte) × 8 ÷ 전송 속도(bps)`**로 계산합니다.

### 1.2 10진수 ↔ 2진수 양방향 초고속 변환 및 연산

시험지에서 나눗셈을 길게 하지 말고, **`64 - 32 - 16 - 8 - 4 - 2 - 1` 자리값**을 적어 즉시 변환합니다.

```
① [2진수 101101(2) ──▶ 10진수 변환] : 1이 있는 자리값만 더하기
   자리값 :   32   16    8    4    2    1
   2진수  :    1    0    1    1    0    1   ──▶  32 + 8 + 4 + 1 = 45

② [10진수 53 ──▶ 2진수 변환] : 큰 자리값부터 뺄 수 있으면 1, 못 빼면 0 적기
   53 = 32 + 16 + 4 + 1 (8과 2는 안 쓰임)
   자리값 :   32   16    8    4    2    1
   2진수  :    1    1    0    1    0    1   ──▶  110101(2)
```
* **2진수 연산 핵심 팁**:
  * **크기 비교 문제**: 보기에 2진수와 10진수가 섞여 나오면 **모두 10진수로 통일**해서 비교하는 것이 가장 빠릅니다.
  * **2진수 덧셈 자리올림**: 각 자리에서 **`1 + 1 = 10(2)`** (현재 자리는 `0`이 되고 윗자리로 `1` 올림), **`1 + 1 + 1 = 11(2)`** (현재 자리 `1`, 윗자리로 `1` 올림)

## 2. 문자 · 이미지 · 소리의 디지털화 원리

### 2.1 미디어별 디지털 표현 핵심 비교

| 구분 | 핵심 원리 및 비교 | 디미고 시험 단골 함정 & 출제 포인트 |
| :---: | :--- | :--- |
| **문자** | **아스키(ASCII)** vs **유니코드(Unicode)** | • **ASCII**: 영문·숫자·기본 기호만 표현 (한글 표현 불가)<br>• **유니코드**: 한글·이모지 등 **전 세계 모든 문자**를 표현하는 국제 표준 |
| **이미지** | **비트맵(Bitmap)** vs **벡터(Vector)** | • **비트맵**: 작은 점(**픽셀, Pixel**)의 모임 → **확대 시 계단 현상(깨짐)** 발생 (사진)<br>• **벡터**: 점·선·면을 **수학 공식**으로 저장 → **확대해도 절대 깨지지 않음** (로고, 글꼴) |
| **소리** | **표본화 → 양자화 → 부호화** | 아날로그 파형을 일정 시간 간격으로 측정(**표본화**) → 정수 눈금값으로 반올림(**양자화**) → 0과 1의 2진수로 변환(**부호화**) |

* **★ 용량과 품질의 비례 법칙**: 이미지의 **해상도(픽셀 수)·색상 비트 수**를 높이거나, 소리의 **표본화 주기를 짧게(자주 추출)·양자화 단계를 세밀하게** 할수록 원본에 가까워지지만 **파일 용량은 커집니다.**

### 2.2 흑백 비트맵 픽셀(0·1) 매핑과 런-랭스(RLE) 압축 (★빈출 퍼즐)

```
[격자 픽셀]   [2진수 표현]     [런-랭스(RLE) 압축: 연속된 개수 적기]
□ ■ ■ ■ □  ──▶  0 1 1 1 0  ──▶  (0,1), (1,3), (0,1)  또는  1, 3, 1
■ □ □ □ ■  ──▶  1 0 0 0 1  ──▶  (1,1), (0,3), (1,1)  또는  0, 1, 3, 1 (※ 첫 칸이 검은색일 때!)
■ ■ ■ ■ ■  ──▶  1 1 1 1 1  ──▶  (1,5)                또는  0, 5       ──▶ 알파벳 'A' 모양!
■ □ □ □ ■  ──▶  1 0 0 0 1  ──▶  (1,1), (0,3), (1,1)  또는  0, 1, 3, 1
```
* **★ RLE 퍼즐 함정**: `"항상 흰색(0)의 개수부터 먼저 적는다"`는 조건이 주어졌을 때, 줄의 **맨 첫 칸이 검은색(`1`)으로 시작하면 맨 앞에 흰색이 0개라는 뜻인 `0`을 반드시 먼저 적어야** 합니다!

### 3.2 데이터 구조화 3대 모델과 실전 문제 유형

```
[ ① 표 (Table): 행·열 비교 ]     [ ② 트리 (Tree): 상하 계층 ]       [ ③ 그래프 (Graph): 연결망 ]
  ┌──────┬──────┬──────┐              ( 루트: 최상위 노드 )              (A역) ─── 4분 ─── (B역)
  │ 이름 │ 국어 │ 수학 │                   /         \                     │                 │
  ├──────┼──────┼──────┤             ( 음악 )       ( 문서 )              2분               3분
  │ 김디 │  95  │  90  │              /    \           │                   │                 │
  └──────┴──────┴──────┘          (발라드) (팝)    (보고서)              (C역) ─── 6분 ─── (D역)
```
* **트리(Tree) 출제 유형**: 폴더 구조나 대진표에서 **루트 노드**(맨 위 출발점), **부모-자식 관계**, **단말 노드**(자식이 없는 맨 끝 노드: 위 그림에서 `발라드`, `팝`, `보고서` 3개)의 개수 찾기
* **그래프(Graph) 출제 유형**: 정점(역/도시)과 간선(소요 시간/거리 숫자)이 주어진 노선도에서 **`A역 → D역`으로 가는 최단 시간 경로**(`A→B→D = 7분` vs `A→C→D = 8분` → 정답 7분) 계산하기
* **상관관계 해석 주의점**:
  * **양(+)의 상관관계**: `X`가 증가할 때 `Y`도 증가 / **음(-)의 상관관계**: `X`가 증가할 때 `Y`는 감소
  * **인과관계 혼동 금지**: 두 변수가 비례해 움직인다고 해서(상관관계) 반드시 원인과 결과(인과관계)인 것은 아닙니다.
