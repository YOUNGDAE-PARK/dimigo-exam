# Ⅲ. 알고리즘과 프로그래밍 (디미고 소질·적성검사 핵심 요약)

> **디미고 실전 출제 유형 4가지**:  
> ① **순서도(Flowchart) 반복 루프 변수 값 손추적 및 빈칸 조건 채우기**  
> ② **두 변수의 값 교환(SWAP) 3단계 순서 배열**  
> ③ **나머지 연산(배수·짝홀수 판별) 및 논리 연산(`AND`, `OR`, `NOT`) 진리값 판별**  
> ④ **리스트(배열) 인덱스 값 참조 및 문법 오류 vs 논리 오류 구분**

## 1. 문제 추상화와 알고리즘의 성질

### 1.1 문제 상태 정의와 추상화

```
┌──────────────────────────────────┐      ┌──────────────────────────────────┐
│     1. 문제 상태 정의 (구조화)   │      │       2. 문제 분해 및 추상화     │
├──────────────────────────────────┤ ───▶ ├──────────────────────────────────┤
│ • 초기 상태: 출발점 / 주어진 조건│      │ • 문제 분해: 큰 문제를 해결하기  │
│ • 현재 상태: 규칙 적용 중인 상태 │      │   쉬운 작은 단계로 나누기        │
│ • 목표 상태: 최종 도달할 결과    │      │ • 추상화: 불필요한 세부사항 제거,│
│   (상태 변화 규칙·제약조건 파악) │      │   문제 해결의 '핵심 요소'만 추출 │
└──────────────────────────────────┘      └──────────────────────────────────┘
```
* **★ 추상화 실전 예시**: 지하철 환승 앱을 만들 때 '역 이름, 노선 연결, 소요 시간'만 남기고(핵심 요소 추출), '실제 철길의 구부러진 모양, 역 주변 건물, 열차 색깔'을 지우는 것(불필요한 세부사항 제거)이 바로 **추상화**입니다.

### 1.2 알고리즘의 3대 필수 조건과 표현 방법
* **알고리즘 성립 조건**: **명확성**(모호한 표현 금지) · **유한성**(언젠가 반드시 종료되어야 함, 무한 루프 불가) · **수행 가능성**(실제로 처리 가능해야 함)
* **3대 표현 방법**: **자연어**(일상 언어, 의미가 모호해지기 쉬움) / **의사코드**(프로그래밍 구조와 비슷한 가짜 코드) / **순서도**(도형과 화살표로 논리 흐름을 시각화)

## 2. 순서도(Flowchart)와 반복 루프 손추적 공식

### 2.1 순서도 표준 기호와 3대 제어 구조

```
[순서도 4대 기호]  ( 시작/종료 ): 타원  |  / 입출력 /: 평행사변형  |  [ 처리/연산 ]: 직사각형  |  < 조건판단 >: 마름모

 ① 순차 구조 (위→아래 차례로)   ② 선택 구조 (조건 분기)       ③ 반복 구조 (조건 동안 회전)
       [ 처리 A ]                   < 조건식? >             ┌──▶ < 반복 조건? > ──(거짓)──▶ 종료
           │                       / (참)      \ (거짓)     │         │ (참)
           ▼                      ▼             ▼           │    [ 반복 실행문 ]
       [ 처리 B ]             [실행 A]       [실행 B]       └─────────┘
```

### 2.2 ★ 시험 1순위: 반복문 누적 합계(`S ← S + i`) 손추적 표 작성법

순서도에서 **`S ← S + i`**는 "기존 `S` 값에 `i`를 더해서 다시 `S`에 저장(누적)하라"는 뜻입니다. 시험지 여백에 반드시 아래처럼 **변수 추적표(Trace Table)**를 그려서 풉니다.

```
[문제 예시: 초기값 S ← 0, i ← 1 / 조건: i ≤ 4 인 동안 (S ← S + i, i ← i + 1) 반복 후 S 출력]

  ┌──────────┬──────────────┬─────────────────┬───────────────┐
  │ 회전차수 │ 조건(i ≤ 4?) │ 누적 (S ← S + i)│ 증가 (i ← i+1)│
  ├──────────┼──────────────┼─────────────────┼───────────────┤
  │   초기   │      -       │      S = 0      │     i = 1     │
  │  1회전   │ 1 ≤ 4 (참)   │  S = 0 + 1 = 1  │     i = 2     │
  │  2회전   │ 2 ≤ 4 (참)   │  S = 1 + 2 = 3  │     i = 3     │
  │  3회전   │ 3 ≤ 4 (참)   │  S = 3 + 3 = 6  │     i = 4     │
  │  4회전   │ 4 ≤ 4 (참)   │  S = 6 + 4 = 10 │     i = 5     │
  │   종료   │ 5 ≤ 4 (거짓) │  루프 탈출!     │ 최종 출력 S=10│
  └──────────┴──────────────┴─────────────────┴───────────────┘
  ※ 함정 주의: 종료 시점의 i 값은 4가 아니라 5입니다! 문제가 S를 묻는지 i를 묻는지 꼭 확인하세요.
```

## 3. 변수 교환(SWAP) · 리스트 · 연산자 · 디버깅

### 3.1 두 변수의 값 교환 (SWAP 3단계 꼬리물기 공식)

`A = 10`, `B = 20`일 때 `A ← B`를 바로 실행하면 기존 `A`의 값(`10`)이 지워져 버립니다 (`A=20, B=20`). 따라서 반드시 **빈 상자(`TEMP`)**가 필요합니다.

```
  1단계: TEMP ← A    (A의 값 10이 지워지기 전에 TEMP에 대피)   [TEMP: 10, A: 10, B: 20]
  2단계: A ← B       (B의 값 20을 A에 덮어씌움)                [TEMP: 10, A: 20, B: 20]
  3단계: B ← TEMP    (대피시켜 둔 TEMP의 값 10을 B에 저장)     [TEMP: 10, A: 20, B: 10]
  (※ 꼬리물기 암기법: TEMP ──▶ A / A ──▶ B / B ──▶ TEMP 순서로 대각선 연결!)
```

### 3.2 리스트(배열)와 나머지·논리 연산자

* **리스트 (List / Array)**: 여러 데이터를 연속된 공간에 저장하고 **위치 번호(인덱스)**로 접근하는 구조
  * **★ 인덱스 시작 번호 주의**: 지문에서 첫 번째 칸을 **`0`번(`A[0]`)**으로 정의하는지, **`1`번(`A[1]`)**으로 정의하는지 반드시 먼저 확인합니다.
* **나머지 연산 (`MOD` 또는 `%`) 활용 공식** (순서도 조건문 단골!):
  * `N을 2로 나눈 나머지 == 0` ──▶ **짝수 판별** (나머지가 `1`이면 **홀수**)
  * `N을 K로 나눈 나머지 == 0` ──▶ **`K`의 배수(약수) 판별**
* **논리 연산자 3종 (`AND`, `OR`, `NOT`)**:

| 조건 P | 조건 Q | `P AND Q` (둘 다 참일 때만 참) | `P OR Q` (하나라도 참이면 참) | `NOT P` (참↔거짓 반전) |
| :---: | :---: | :---: | :---: | :---: |
| **참(T)** | **참(T)** | **참 (T)** | **참 (T)** | 거짓 (F) |
| **참(T)** | 거짓(F) | 거짓 (F) | **참 (T)** | 거짓 (F) |
| 거짓(F) | **참(T)** | 거짓 (F) | **참 (T)** | **참 (T)** |
| 거짓(F) | 거짓(F) | 거짓 (F) | 거짓 (F) | **참 (T)** |

### 3.3 함수(Function)와 디버깅(오류 구분)
* **함수 (Function)**: 반복되는 코드를 하나로 묶어 재사용하는 모듈 (`입력값: 매개변수/인자` → `함수 처리` → `출력값: 반환값 Return`)
* **오류(Bug)의 2가지 유형 비교**:
  * **문법 오류 (Syntax Error)**: 철자 오타, 괄호 누락 등 문법 규칙 위반으로 **실행 자체가 안 되는 오류**
  * **논리 오류 (Logical Error)**: 실행은 정상적으로 되지만, **알고리즘/조건식을 잘못 짜서 의도와 다른 엉뚱한 결과가 나오는 오류** (예: 평균을 구할 때 괄호를 안 쳐서 `국어 + 수학 ÷ 2`로 계산한 경우)
