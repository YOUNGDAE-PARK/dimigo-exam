🎯 [스쿨배틀 완전 내재화 마스터플랜] 아빠의 MVP를 딸의 진짜 프로젝트로 체화하는 실전 가이드

문서 목적: 개발자인 아버지가 구축한 <스쿨배틀> MVP를, 박윤하 학생이 자신의 철학, 경험, 언어로 100% 흡수(내재화)하여 디미고 심층면접관의 어떤 송곳 검증도 당당하게 통과하도록 만드는 실전 트레이닝 계획서
핵심 원칙: "외워서 연기하는 학생은 1분 만에 들통납니다. 직접 경험하고, 직접 말해보고, 기획자의 논리를 자기 것으로 만든 학생만이 합격합니다."

🧭 1. 심사위원의 '부모·대리 개발' 감별 메커니즘

디미고 면접관(전공 교사 및 외부 IT 전문가)은 중학생이 가져온 완성도 높은 결과물을 볼 때 99% "부모나 학원이 대신 해준 것 아닌가?"라는 의심부터 시작합니다. 면접관은 다음 세 가지 방식으로 대리 개발 여부를 즉각 감별해 냅니다.

[면접관의 3단계 대리 개발 감별법]
1. Why 질문 (기획 의도)   : "왜 이 버튼을 여기 배치했고, 왜 10초 제한 시간으로 정했나요?"
   👉 대리 개발: 외운 티가 나며, 기능의 당위성을 설명하지 못하고 당황함.
   👉 진짜 기획: "친구들과 문제집 풀 때 10초가 넘어가면 딴짓을 하더라고요..." 즉각 경험이 나옴.

2. How 질문 (인터랙션 흐름): "학생이 틀렸을 때 시스템 내부에서 오답 던전으로 데이터가 어떻게 넘어가나요?"
   👉 대리 개발: 전문 용어를 쓰려다 꼬이거나 화면 플로우를 헷갈림.
   👉 진짜 기획: 화면을 눈앞에 보듯 손짓하며 화면 전환과 유저 경험을 술술 설명함.

3. Trouble 질문 (문제 해결): "만들면서 제일 화났던 버그나 실패했던 코드가 무엇인가요?"
   👉 대리 개발: 추상적으로 "코드가 잘 안 돌아갔는데 고쳤다"고 뭉뚱그림.
   👉 진짜 기획: "탭을 바꿀 때마다 화면이 계속 깜빡여서 미치는 줄 알았는데..." 구체적 감정이 나옴.

🛠️ 2. 윤하의 4단계 완전 내재화 프레임워크 (Framework)

윤하가 이 프로젝트의 "진짜 주인"이 되기 위해 다음 4단계를 순서대로 밟아야 합니다.

[1단계: 기획 철학 내재화]  ──▶  [2단계: 화면/UX 도슨트화]  ──▶  [3단계: 방어용 기술 스토리]  ──▶  [4단계: 실전 유저 피드백]
  "왜 만들었는가?"                "눈감고도 화면 그리기"          "내가 해결한 버그 2가지"        "실제 친구 시연 경험"
  (아빠 논리 ➔ 윤하 경험)        (1인칭 시제품 시연 해설)        (AI와의 협업 디버깅 실체)       (진짜 피드백 에피소드)

[1단계] 기획 철학 내재화: "아빠의 아이디어를 윤하의 기억으로 바꾸기"

아버지가 설계한 기능들을 윤하의 학교생활기록부와 실제 중학교 생활 경험에 1:1로 결합(Re-framing)해야 합니다.

스쿨배틀 기능 아빠의 개발 관점 (원래 의도) ➔ 윤하가 말해야 할 기획 스토리 (내재화된 언어)
무가입 1초 매칭 로그인 세션 및 DB 부하 감소, 빠른 온보딩 "친구들은 회원가입 창만 뜨면 귀찮아서 바로 앱을 꺼버려요. 쉬는 시간 10분 안에 한 판 하려면 무조건 1초 만에 시작해야 해요."
10초 타임어택 (2배 데미지) 게임적 긴장감 부여, 점수 차별화 로직 "종이 문제집 풀 때는 세월아 네월아 하던 친구들이 게임할 때는 0.1초 만에 반응해요. 초반 3초 안에 맞히면 승부욕이 폭발하게 만들었어요."
오답 던전 (Shadow Raid) 리텐션(재방문율) 증대 메커니즘 "친구가 게임 입장권 더 얻으려고 억지로라도 틀린 문제를 다시 풀게 만드는 '합법적 공부 강제 장치'예요."
교사용 시험 감지 모드 탭 전환 감지 브라우저 API 활용 "수행평가 볼 때 애들이 몰래 네이버 검색하는 걸 선생님들이 제일 싫어하세요. 탭만 딴 데로 넘어가면 바로 경고창 뜨게 설계했어요."

[2단계] 화면/UX 도슨트화: "눈감고도 화면을 설명하는 1인칭 시연 훈련"

윤하가 시제품을 남의 프로그램 보듯 만지면 탈락합니다. 미술관 도슨트(해설사)처럼 자유자재로 다룰 수 있어야 합니다.

  1. A4 종이에 손으로 와이어프레임(화면 흐름도) 그리기 훈련
    • 윤하에게 빈 종이를 주고 로비 화면 ➔ 매칭 화면 ➔ 배틀 화면 ➔ 오답 던전 ➔ 교사 대시보드를 직접 손으로 네모 칸을 치며 그려보게 합니다.
    • "이 버튼을 누르면 어떤 팝업이 뜨고 어디로 이동하지?"를 스스로 그리면서 설명할 수 있어야 머릿속에 완전히 각인됩니다.
  2. 소리 내어 설명하는 '3분 무편집 시연' 3회 연속 연습
    • 아빠 앞에서 화면을 직접 클릭하면서 3분 영상 시나리오대로 끊김 없이 시연하는 훈련을 합니다.
    • 마우스 커서의 움직임 하나하나에 기획자의 의도가 실려 있어야 합니다.

[3단계] 방어용 기술 스토리 내재화: "중3 수준에 딱 맞는 정직한 테크 답변"

면접관이 "어디까지 본인이 짰느냐?"고 물었을 때, 코드를 완벽히 안다고 거짓말하면 절대 안 됩니다. "기획과 구조는 내가 100% 설계했고, 구현은 AI(Claude)의 도움을 받아 디버깅하며 배웠다"는 프레임이 가장 완벽합니다. 윤하는 다음 2가지 기술 에피소드를 자기 경험으로 말할 수 있어야 합니다.

💡 윤하가 반드시 외우고 이해해야 할 2대 기술 에피소드

  1. 에피소드 A: visibilitychange 화면 이탈 감지 에러 (시험 모드)
    • 상황: 학생들이 시험 도중 다른 탭을 열어 검색하는 부정행위를 막으려고 브라우저 이탈 감지 코드를 넣음.
    • 윤하의 멘트:

      "선생님 대시보드에 부정행위 방지 기능을 넣으려고 검색해 보니 자바스크립트에 document.addEventListener('visibilitychange')라는 이벤트가 있더라고요.
      이걸 리액트 컴포넌트에 넣었더니 탭을 한 번 바꿀 때마다 경고창이 수십 개씩 무한대로 뜨는 버그가 났어요.
      AI한테 물어보니까 컴포넌트가 다시 그려질 때마다 이벤트가 계속 새로 등록돼서 그렇다면서, 리액트 useEffect 안에서 return () => removeEventListener로 클린업(정리)을 해줘야 한다고 알려줬어요. 그때 '아, 리액트는 일반 자바스크립트랑 다르게 컴포넌트 생명주기를 신경 써야 하는구나'를 확실히 배웠습니다."

  2. 에피소드 B: 10초 타임어택 타이머 비동기 오차 에러 (배틀 모드)
    • 상황: 10초 카운트다운 타이머가 정답을 눌렀는데도 멈추지 않고 계속 내려감.
    • 윤하의 멘트:

      "퀴즈를 맞히면 타이머가 멈추고 점수를 계산해야 하는데, setInterval로 만든 타이머가 제가 정답 버튼을 눌렀는데도 0초가 될 때까지 계속 도는 거예요.
      상태값(isAnswered)이 바뀌었는데도 비동기 타이머 안에서는 예전 상태를 바라보고 있는 '클로저(Closure) 문제'라는 걸 알게 되었어요. 타이머의 ID를 useRef나 상태로 기억해 뒀다가 정답을 누르는 순간 clearInterval로 즉시 죽여주는 로직을 짜면서 비동기 처리의 어려움을 체감했습니다."

[4단계] 실전 플레이 경험 만들기: "윤하가 직접 유저를 관찰한 진짜 에피소드 확보"

예선은 서류 심사이지만, 합격 후 특별전형 심층면접에서 "이 서비스를 주변 사람에게 보여준 적이 있느냐?"는 질문이 나올 가능성이 높습니다. 윤하가 실제로 친구나 가족에게 프로토타입을 플레이시켜 보고, 그때의 반응을 자신의 경험으로 축적해야 면접에서 살아있는 눈빛으로 답할 수 있습니다.

  1. 가족 또는 친구 2~3명과 실제 플레이 세션 진행
    • 노트북이나 태블릿으로 battle-study를 켜주고 실제로 퀴즈를 풀게 합니다.
    • 옆에서 상대방이 어디서 헷갈려 하는지, 언제 "와!" 하고 소리를 지르는지 윤하가 메모지에 직접 적습니다.
  2. 생생한 피드백 한 문장 확보하기
    • 예상 반응: "야, 10초 너무 짧아. 문제 읽다가 끝나잖아!"
    • ➔ 이 한마디를 윤하가 직접 들어봐야, 면접관 앞에서 "프로토타입을 친구한테 직접 보여줬는데 10초가 너무 촉박하다고 해서 초반엔 시간을 더 주는 동적 난이도 조절을 구상하게 되었습니다"라고 진정성 있게 말할 수 있습니다.

🛡️ 4. 면접관의 "부모 대리 개발" 의혹을 무력화하는 필살 답변

만약 면접관이 직설적으로 묻는다면, 윤하는 다음과 같이 답변해야 100점 만점을 받습니다.

Q. [돌직구 질문] "프로젝트가 중학생 수준치고 너무 완성도가 높은데, 부모님이나 학원의 도움을 받은 것 아닌가요?"

윤하의 모범 답변:
"솔직히 말씀드리면, 저희 아버지가 SW 개발자이셔서 제가 막히는 기술적 부분에서 큰 조언과 멘토링을 주신 것은 사실입니다.
하지만 '어떤 문제를 해결할 것인가', '어떤 화면과 게임 규칙을 넣을 것인가'에 대한 기획과 서비스 구조는 100% 제가 주도했습니다.
저는 중학교에서 학생자치회 카드뉴스를 도입했던 경험과 친구들이 게임에 몰입하는 모습을 보며 이 아이디어를 냈고, 손으로 화면 흐름도를 그린 뒤 Next.js 프로토타입을 만드는 과정에서 아버지께 문법적 질문을 드리고 AI 도구를 활용해 디버깅했습니다.
아버지는 제게 코드를 대신 짜주신 것이 아니라, 제가 구상한 기획을 웹 표준에 맞게 구현할 수 있도록 길을 열어주신 멘토이셨습니다. 이 프로토타입의 기획 의도와 세부 인터랙션 하나하나는 모두 제 머리와 손끝에서 나온 저의 진짜 결과물입니다."
