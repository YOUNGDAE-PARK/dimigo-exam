1. 명제와 부울 대수 (Proposition & Boolean Logic)

1.1 명제(Proposition)와 진리값(Truth Value)

  • 명제: 객관적인 기준에 의해 참(True, 1)인지 거짓(False, 0)인지를 명확하게 판별할 수 있는 문장이나 수학 식입니다.
    • 명제인 것: "8은 2의 배수이다." (참), "고양이는 날개가 있다." (거짓), "3+5=10" (거짓)
    • 명제가 아닌 것: "이 컴퓨터 게임은 재미있다." (주관적 감정), "X+2=5" (X값에 따라 달라지는 '조건')
  • 진리값: 명제가 갖는 실제 논리적 상태인 '참(T)' 또는 '거짓(F)'을 말합니다.

1.2 4대 핵심 논리 연산자 (Logical Operators)

컴퓨터의 디지털 회로와 프로그래밍 조건문은 다음 4가지 기본 논리 연산의 조합으로 동작합니다.

논리 연산자 기호 / 키워드 참이 되는 조건 실전 진리표 요약
AND (논리곱) ∧, 그리고 관련된 모든 조건이 100% 참일 때만 참 하나라도 거짓이면 무조건 거짓
OR (논리합) ∨, 또는 조건 중 적어도 하나라도 참이면 참 둘 다 거짓일 때만 거짓
NOT (논리부정) ∼, ¬, 반대 진리값을 반대로 뒤집음 참 ➔ 거짓, 거짓 ➔ 참
XOR (배타적 논리합) ⊕, 서로 다름 두 조건이 서로 다를 때만 참 둘 다 참이거나 둘 다 거짓이면 거짓

1.3 드모르간의 법칙 (De Morgan's Laws)

복잡하게 얽힌 조건문을 단순화할 때 사용하는 가장 강력한 수학적 논리 도구입니다.

  1. NOT(A AND B)=(NOT A) OR (NOT B)
    "A와 B 둘 다 만족하는 것은 아니다" = "A가 아니거나, 또는 B가 아니다"
  2. NOT(A OR B)=(NOT A) AND (NOT B)
    "A 또는 B 중 하나이다의 부정" = "A도 아니고, 동시에 B도 아니다"
  • ★ 100점 만점 실전 팁: 알고리즘 조건문 문제에서 !(나이 >= 14 && 점수 > 80)이 제시되면, 드모르간 법칙을 적용하여 (나이 < 14 || 점수 <= 80)으로 즉시 변환해야 계산 시간을 획기적으로 줄일 수 있습니다.

2. 역·이·대우와 삼단논법 (Principles of Deduction)

2.1 조건 명제의 3대 변형

기본 조건 명제 "P이면 Q이다 (P→Q)"가 주어졌을 때:

구분 명칭 기호 표기 원래 명제와의 참/거짓 일치 여부
기본 명제 조건 명제 P→Q "비가 오면 운동장이 젖는다." (참)
역 (Converse) 앞뒤 순서 바꾸기 Q→P "운동장이 젖어 있다면 비가 온 것이다." ➔ 항상 참은 아님 (스프링클러일 수도 있음)
이 (Inverse) 앞뒤 각각 부정하기 ∼P→∼Q "비가 오지 않으면 운동장이 젖지 않는다." ➔ 항상 참은 아님
대우 (Contrapositive) 순서도 바꾸고 둘 다 부정 ∼Q→∼P "운동장이 젖어 있지 않다면 비가 오지 않은 것이다." ➔ 무조건 100% 참!

📌 시험 절대 불변 법칙 (대우의 법칙):
"어떤 명제가 참이면, 그 대우 명제는 증명할 필요도 없이 무조건 100% 참이다!"
(반면, 역과 이는 원래 명제와 참/거짓이 일치할 수도 있고 다를 수도 있으므로 절대 섣불리 참이라고 단정하면 안 됩니다.)

2.2 징검다리 삼단논법 (Syllogism)

  • 기본 형태: P→Q 가 참이고 Q→R 이 참이면, 중간 다리 Q를 건너뛰고 P→R 도 반드시 참이 됩니다.
  • ★ 디미고 킬러 함정 패턴 (대우 결합형 삼단논법):
    시험에서는 연결고리를 한눈에 보이지 않게 꼬아둡니다.
    • 전제 1: "컴퓨터를 좋아하는 학생은 수학을 잘한다." (A→B)
    • 전제 2: "논리적이지 않은 학생은 수학을 잘하지 못한다." (∼C→∼B)
    • 해결 공식: 전제 2의 대우를 구하면 B→C ("수학을 잘하면 논리적이다")가 됩니다.
    • 따라서 A→B→C 로 연결되어, "컴퓨터를 좋아하는 학생은 논리적이다 (A→C)"라는 확실한 결론을 도출할 수 있습니다.

3. 참말/거짓말쟁이 판별 퍼즐 (Truth-teller & Liar Puzzles)

수험생들이 가장 시간을 많이 빼앗기는 유형입니다. 무작정 모든 경우를 상상하지 말고, 다음 3단계 공략 공식을 기계적으로 적용해야 합니다.

[1단계: 상호 모순 포착] ➔ 서로 정반대 진술을 하는 2명을 찾아 묶음 (둘 중 1명은 참, 1명은 거짓)
[2단계: 진실 인원 차감] ➔ 전체 참말쟁이 수에서 1명을 빼고, 나머지 사람들의 진위 즉시 확정
[3단계: 귀류법 검증]   ➔ 남은 조건에서 말이 안 되는 충돌(모순)이 없는지 확인

📝 실전 예제 1 (범인 찾기)

A, B, C, D 4명의 학생 중 1명이 교실 유리창을 깼습니다. 4명 중 단 1명만 진실(참말)을 말하고 있을 때, 실제로 유리창을 깬 범인은 누구일까요?

  • A: "B가 유리창을 깼습니다."
  • B: "D가 유리창을 깼습니다."
  • C: "저는 깨지 않았습니다."
  • D: "B의 말은 거짓말입니다."

✅ 단계별 풀이 과정:

  1. 상호 모순 발견: B는 "D가 깼다"고 하고, D는 "B의 말은 거짓말"이라고 하므로, B와 D 중 한 명은 반드시 참말이고 다른 한 명은 거짓말입니다.
  2. 나머지 인원 확정: 진실을 말하는 사람이 단 1명뿐이므로, 그 1명은 {B, D} 그룹 안에 있습니다. 따라서 A와 C는 무조건 100% 거짓말쟁이입니다!
  3. 결론 도출:
    • C가 "저는 깨지 않았습니다"라고 거짓말을 했으므로, C의 진술을 부정한 결론, 즉 실제 유리창을 깬 범인은 바로 C입니다!
    • (검증: 범인이 C이면 A는 거짓, B는 거짓, D는 참말, C는 거짓으로 정확히 1명만 참말이 되어 완벽히 성립합니다.)

4. 조건 추리 및 2차원 그리드 소거법 (Grid Deduction)

이름, 등수, 취미, 학과 등을 짝짓는 복잡한 조건 추리 문제는 머리로 풀면 100% 함정에 빠집니다. 시험지 여백에 2차원 매트릭스 표(Grid Table)를 그리고, 확실한 단서부터 O, X로 채워 나가야 합니다.

📝 실전 예제 2 (방 배정 퍼즐)

민호, 수진, 현우 3명이 각각 101호, 102호, 103호에 한 명씩 살고 있습니다. 각자의 전공 학과는 해킹방어과, 웹프로그래밍과, e-비즈니스과 중 하나입니다.

  • [단서 1] 민호는 103호에 살지 않습니다.
  • [단서 2] 해킹방어과 학생은 101호에 삽니다.
  • [단서 3] 수진이는 e-비즈니스과입니다.
  • [단서 4] 102호에 사는 학생은 웹프로그래밍과가 아닙니다.
    현우의 방 번호와 학과를 각각 구하시오.

✅ 풀이 과정 (소거 매트릭스 활용):

  1. 단서 2와 단서 3을 결합합니다:
    • 해킹방어과는 101호에 살고, 수진이는 e-비즈니스과이므로, 수진이는 101호에 살 수 없습니다 (102호 또는 103호).
  2. 단서 4를 분석합니다:
    • 102호는 웹프로그래밍과가 아니고, 단서 2에 의해 101호가 해킹방어과이므로, 102호는 무조건 e-비즈니스과여야 합니다!
  3. 매칭 완성:
    • 102호 = e-비즈니스과 ➔ 단서 3에 의해 수진 = 102호 (e-비즈니스과) 확정.
    • 남은 방은 101호와 103호입니다. 단서 1에서 민호는 103호가 아니라고 했으므로, 민호 = 101호 (해킹방어과) 확정.
    • 따라서 남은 현우는 현우 = 103호 (웹프로그래밍과)가 됩니다.
  • 정답: 현우는 103호, 웹프로그래밍과

5. ★ 디미고 킬러 유형: 규칙 검증 퍼즐 (Wason Selection Task)

디미고 소질·적성검사 지필고사에서 가장 대표적으로 출제되는 고난도 논리 검증 문제입니다.

💡 핵심 원리: "무엇을 뒤집어 보아야 규칙 위반을 잡을 수 있는가?"

다음 4장의 카드가 책상 위에 놓여 있습니다. 앞면에는 알파벳, 뒷면에는 숫자가 적혀 있습니다.

┌───┐  ┌───┐  ┌───┐  ┌───┐
│ A │  │ B │  │ 4 │  │ 7 │
└───┘  └───┘  └───┘  └───┘
 [P]   [~P]   [Q]    [~Q]

[검증할 규칙]: "카드의 한쪽 면에 모음(A, E, I, O, U)이 적혀 있다면, 다른 쪽 면에는 반드시 짝수가 적혀 있어야 한다." (P→Q)

규칙이 참인지 확인하기 위해 반드시 뒤집어 확인해야 하는 카드는 무엇일까요?

  • 대부분의 오답: 많은 수험생들이 직관적으로 A와 4를 고릅니다. 그러나 이는 오답입니다!
  • 정답 및 대우 논리 해설:
    1. 카드 A (모음, P): 반드시 뒤집어야 합니다. 뒷면에 홀수가 나오면 규칙 위반(P인데 ∼Q)이 되기 때문입니다.
    2. 카드 B (자음, ∼P): 뒤집을 필요가 없습니다. 규칙은 "모음이면 짝수"라고만 했지, 자음 뒷면에 무엇이 와야 하는지는 아무런 제약이 없습니다.
    3. 카드 4 (짝수, Q): 뒤집을 필요가 없습니다. 뒷면에 자음이 나오든 모음이 나오든 규칙 위반이 되지 않습니다 (Q→P인 역은 원래 명제와 무관함).
    4. 카드 7 (홀수, ∼Q): 반드시 뒤집어야 합니다! 규칙 P→Q의 대우는 "뒷면이 짝수가 아니라면(홀수라면), 앞면은 모음이 아니어야 한다(자음이어야 한다) (∼Q→∼P)"입니다. 만약 7의 뒷면에 모음이 적혀 있다면 규칙이 깨집니다!
  • ★ 최종 결론: 반드시 뒤집어야 하는 카드는 A와 7 입니다.

1. 진법 변환과 컴퓨터 데이터 표현 (Base Conversion)

컴퓨터는 전기가 흐르지 않는 상태(0)와 흐르는 상태(1)만을 물리적으로 인식하므로 2진법(Binary)을 근본 체계로 사용합니다. 나아가 긴 2진수 데이터를 효율적으로 줄여 쓰기 위해 16진법(Hexadecimal)을 사용합니다.

1.1 10진수와 2진수의 상호 변환

  • 10진수 ➔ 2진수 (자릿값 분할 쾌속법):
    • 2로 계속 나누어 나머지를 거꾸로 적는 방법도 있지만, 실전에서는 2의 거듭제곱(128, 64, 32, 16, 8, 4, 2, 1)의 합으로 쪼개는 것이 훨씬 빠릅니다.
    • 예시 (10진수 45):
      • 45=32+8+4+1 (25+23+22+20)
      • 해당하는 자리에 1을 넣고, 쓰지 않은 자리(16, 2)에 0을 채우면 ➔ 101101₂
  • 2진수 ➔ 10진수 (자릿값 곱하기):
    • 오른쪽 끝자리부터 1,2,4,8,16,32…의 가중치를 부여해 1이 있는 자리만 더합니다.
    • 예시 (11010₂): 16+8+0+2+0=2610​

1.2 16진수(Hexadecimal)와 4비트 묶음 법칙

  • 16진수는 0부터 15까지 16개의 기호를 사용합니다. 10부터 15까지는 알파벳 대문자 A(10), B(11), C(12), D(13), E(14), F(15)로 표기합니다.
  • ★ 핵심 공식: 2진수 4자리는 16진수 정확히 1자리와 일치합니다 (24=16).
    • 예시 (11101011₂의 16진수 변환):
      • 뒤에서부터 4자리씩 분할: 1110 / 1011
      • 앞 묶음 1110₂ = 8+4+2+0=14 ➔ E
      • 뒤 묶음 1011₂ = 8+0+2+1=11 ➔ B
      • 결과: EB₁₆

1.3 음수 표현과 2의 보수 (Two's Complement)

컴퓨터 내부에는 뺄셈 전용 회로가 없습니다. 덧셈 회로 하나로 뺄셈까지 완벽하게 처리하기 위해 음수를 2의 보수로 표현합니다.

[양수 2진수] ──(비트 반전 0↔1)──➔ [1의 보수] ──(+1 더하기)──➔ [2의 보수 (음수)]
  • [실전 예제] 8비트 체계에서 10진수 -6 표현하기:
    1. +6의 8비트 2진수: 0000 0110
    2. 1의 보수 (모든 비트 반전): 1111 1001
    3. 끝자리에 1 더하기: 1111 1001 + 1 = 1111 1010
  • ★ 100점 만점 팁: 최상위 비트(맨 앞자리, MSB)가 0이면 양수, 1이면 음수입니다.

1.4 비트 시프트 연산 (<<, >>)

  • 좌측 시프트 (X << 1): 모든 비트를 왼쪽으로 1칸 밀고 끝에 0을 채움 ➔ 값이 정확히 2배(×2) 증가.
  • 우측 시프트 (X >> 1): 모든 비트를 오른쪽으로 1칸 밀어냄 ➔ 값이 정확히 절반(÷2, 몫만 남음)으로 감소.

2. 경우의 수와 조합론 (Combinatorics)

2.1 합의 법칙(+)과 곱의 법칙(×)

  • 합의 법칙 (Rule of Sum): 사건 A와 B가 동시에 일어날 수 없을 때 (택일) ➔ 두 경우의 수를 더합니다.
    • 예: 도서관에서 소설책 3권 중 1권을 빌리거나, 과학책 4권 중 1권을 빌리는 경우 = 3+4=7가지.
  • 곱의 법칙 (Rule of Product): 사건 A가 발생한 후 연달아(동시에) 사건 B가 발생할 때 ➔ 두 경우의 수를 곱합니다.
    • 예: 티셔츠 3벌과 청바지 2벌을 짝지어 입는 코디의 수 = 3×2=6가지.

2.2 순열 (Permutation) vs 조합 (Combination)

문제에서 가장 중요한 판단 기준은 "순서(등수/직책)가 존재하는가?"입니다.

구분 순열 (Permutation, nPr) 조합 (Combination, nCr)
순서 유무 순서 고려 O (줄 세우기) 순서 무관 X (모둠/묶음 선택)
대표 상황 반장 1명, 부반장 1명 뽑기, 달리기 1/2등 대표 2명 뽑기, 청소 당번 뽑기, 사람들끼리 악수하기
계산 공식 nPr=n×(n−1)×⋯×(n−r+1) nCr=r!nPr​=r×(r−1)×⋯×1n×(n−1)×⋯​
예시 (5명 중 2명) 5P2=5×4=20가지 5C2=2×15×4​=10가지
  • ★ 빈출 공식: N명이 서로 한 번씩 빠짐없이 악수를 나누는 횟수:
    • 악수는 2명이 짝을 이루는 조합이므로: nC2=2N×(N−1)​
    • (예: 10명이 모두 악수하면 210×9​=45회)

3. 비둘기집 원리와 최악의 수 추론 (Pigeonhole Principle)

디미고 시험에서 "적어도 ~개가 보장되기 위한 최소 횟수"를 묻는 단골 고난도 킬러 유형입니다.

3.1 비둘기집 원리의 정의

N개의 비둘기집에 N+1마리 이상의 비둘기가 들어간다면, 적어도 어느 하나의 비둘기집에는 2마리 이상의 비둘기가 반드시 들어있어야 합니다.

3.2 시험 최빈출 패턴: 최악의 시나리오(Worst-Case) 기법

  • [문제 상황]: 상자 속에 빨간 공 8개, 파란 공 6개, 노란 공 5개가 섞여 있습니다. 상자 안을 보지 않고 공을 꺼낼 때, 같은 색깔의 공 2개를 확실하게 얻기 위해 꺼내야 하는 최소 공의 개수는 몇 개일까요?
  • 풀이 비법 (세상에서 가장 운이 나쁜 경우를 가정):
    1. 1번째 공: 빨간 공
    2. 2번째 공: 파란 공 (색이 갈라짐)
    3. 3번째 공: 노란 공 (모든 색깔의 공이 1개씩만 나와서 아직 한 쌍이 안 됨!)
    4. 4번째 공: 이제 빨강, 파랑, 노랑 중 어느 색이 나오더라도 반드시 기존에 꺼낸 공과 2개 한 쌍을 완성하게 됩니다!
  • 정답: 색깔 종류의 수(3) + 1 = 4개

4. 그래프 이론과 오일러 경로 (Graph & Eulerian Path)

4.1 정점, 간선, 그리고 악수 정리 (Handshaking Lemma)

  • 정점 (Vertex / Node): 데이터를 담는 점.
  • 간선 (Edge): 정점과 정점을 연결하는 선.
  • 차수 (Degree): 특정 한 정점에 연결되어 있는 간선의 개수.
  • ★ 악수 정리 (절대 공식):
모든 정점의 차수의 총합=전체 간선(선) 개수×2
  • 이유: 선 하나는 양 끝에 2개의 정점을 동시에 연결하기 때문입니다.
  • 핵심 따름정리: 차수가 홀수인 정점(홀수점)의 개수는 항상 짝수 개(0개, 2개, 4개...)여야만 합니다.

4.2 한붓그리기 (오일러 경로, Eulerian Path)

연필을 종이에서 떼지 않고 모든 선을 단 한 번씩만 지나서 전체 도형을 그리는 퍼즐입니다.

구분 성립 조건 시작점과 끝점의 위치
오일러 회로 (Eulerian Circuit) 홀수점이 0개 (모든 점이 짝수점) 어느 점에서 출발해도 출발했던 바로 그 점으로 귀환
오일러 경로 (Eulerian Path) 홀수점이 정확히 2개 한 홀수점에서 출발하여 다른 홀수점에서 종료
한붓그리기 불가능 홀수점이 4개 이상 어떤 방법으로도 한붓그리기 불가

4.3 격자 도로망 최단 경로 카운팅

바둑판 도로망에서 최단 경로의 수를 구할 때는 공식을 외우기보다, 합의 법칙을 이용해 각 교차점에 도달하는 경우의 수를 누적해서 적어나가는 것이 가장 빠르고 실수 없습니다.

5. 트리(Tree)의 수학적 성질 (Tree Properties)

트리는 컴퓨터 과학에서 계층형 데이터(파일 폴더, HTML 문서 구조, 탐색 알고리즘)를 표현하는 핵심 구조입니다.

5.1 트리의 3대 절대 성질

  1. 사이클(순환선)이 전혀 없는 연결 그래프입니다.
  2. 임의의 두 노드 사이를 잇는 경로는 오직 하나뿐입니다.
  3. ★ 정점과 간선의 절대 공식:
간선의 수 (E)=정점의 수 (V)−1
  • 예시: 노드가 50개인 트리의 간선 개수는 묻지도 따지지도 않고 49개입니다!

5.2 이진 트리(Binary Tree)의 노드 수 공식

  • 모든 부모 노드가 최대 2개의 자식 노드를 가지는 트리입니다.
  • 높이(깊이)가 k인 포화 이진 트리(모든 리프가 꽉 찬 트리)의 총 노드 수는:
총 노드 수=2k−1
  • 높이 3인 이진 트리: 23−1=7개 노드
  • 높이 4인 이진 트리: 24−1=15개 노드

1. 순서도 (Flowchart) 읽기와 기호 판독

순서도(Flowchart)는 문제 해결의 절차(알고리즘)를 국제 표준 기호와 화살표로 시각화한 도면입니다.

         [ 시작 (Start) ] ── (타원: 시작과 종료)
                │
                ▼
       [ X = 1, SUM = 0 ] ── (직사각형: 처리/연산/대입)
                │
                ▼
     ┌─＜ X <= 5 ? ＞────┐ ── (마름모: 조건 판단 갈림길)
     │       │ (Yes, 참)  │ (No, 거짓)
     │       ▼           ▼
     │ [ SUM = SUM + X ] [ PRINT(SUM) ] ── (평행사변형: 입출력)
     │ [ X = X + 1     ] │
     │       │           ▼
     └───────┘    [ 종료 (End) ]

💡 주요 표준 기호 총정리

  • 타원 (Terminal): 프로그램의 시작(Start)과 종료(End)를 나타냅니다.
  • 직사각형 (Process): 계산, 데이터 대입 등 실제 명령을 실행합니다 (SUM = SUM + I).
  • 마름모 (Decision): 참(Yes) 또는 거짓(No)에 따라 실행 경로가 나뉘는 조건 판단 분기점입니다 (I > 10?).
  • 평행사변형 (Data / I/O): 외부 입력을 받거나(READ), 최종 결과를 화면에 출력(PRINT)합니다.

2. 변수와 다중 제어 구조 상태 추적 (Tracing Algorithm)

알고리즘 문제의 90%는 머리가 아니라 손으로 풉니다. 코드가 한 줄씩 실행될 때마다 변수 안의 값이 어떻게 변하는지 빈 종이에 변수 추적표(Trace Table)를 그려가며 풀어야 실수를 원천 차단할 수 있습니다.

2.1 대입 연산자 (=) 와 SWAP 알고리즘

  • 프로그래밍에서 =는 수학의 '같다'가 아니라, "오른쪽 계산 결과를 왼쪽 변수 상자에 덮어쓰라"는 명령입니다.
    • X = X + 1 ➔ 현재 X에 1을 더한 값을 다시 X에 덮어씀 (X가 1 증가).
  • SWAP (값 맞바꾸기) 알고리즘:
    두 변수 A와 B의 값을 맞바꿀 때는 반드시 임시 변수 TEMP가 필요합니다.
    TEMP = A;   // 1. A의 기존 값을 TEMP에 임시 보관
A = B;      // 2. B의 값을 A에 덮어씀
B = TEMP;   // 3. 임시 보관해 둔 원래 A의 값을 B에 저장
    (만약 TEMP 없이 A=B; B=A; 를 실행하면 A의 원래 값이 지워져 두 변수 모두 B의 값으로 같아지는 치명적 버그가 발생합니다.)

2.2 중첩 반복문(Nested Loops) 실전 추적 훈련

실전 시험에는 반복문 안에 또 다른 반복문이 들어있는 2중 중첩 반복문이 단골로 출제됩니다.

[추적 예제] 다음 코드가 종료된 후 화면에 출력되는 CNT의 값은?

CNT = 0
FOR (I = 1 to 3) {
    FOR (J = 1 to 2) {
        CNT = CNT + I * J
    }
}
PRINT(CNT)

✅ 변수 추적표 (Trace Table):

외부 루프 I 내부 루프 J 연산 식 (I * J) 누적 연산 (CNT = CNT + I*J) 현재 CNT 값
시작 전 - - - 0
I = 1 J = 1 1×1=1 CNT = 0 + 1 1
J = 2 1×2=2 CNT = 1 + 2 3
I = 2 J = 1 2×1=2 CNT = 3 + 2 5
J = 2 2×2=4 CNT = 5 + 4 9
I = 3 J = 1 3×1=3 CNT = 9 + 3 12
J = 2 3×2=6 CNT = 12 + 6 18
  • 최종 출력: PRINT(CNT) ➔ 18

3. 블랙박스 함수 규칙 추론 (Function & Pattern)

내부 공식이 가려진 변환 상자(블랙박스 함수)에 숫자를 입력했을 때의 입출력 표를 분석하여, 숨겨진 함수 f(x)를 찾아내는 퍼즐입니다.

입력 (x) 출력 (y) 규칙 분석 (힌트 찾기)
2 7 2에 3배 하면 6 ➔ 1이 부족함 (+1)
3 10 3에 3배 하면 9 ➔ 1이 부족함 (+1)
5 16 5에 3배 하면 15 ➔ 1이 부족함 (+1)
8 ? y=3x+1 규칙 성립! ➔ 3×8+1=25
  • 규칙 도출 2단계 공식:
    1. 기울기(변화율) 찾기: x가 1 커질 때 y가 3씩 커지므로, 입력값에 3을 곱하는 항(3x)이 기본입니다.
    2. 상수 보정하기: 3×2=6인데 출력이 7이므로, 뒤에 +1을 더해 f(x)=3x+1을 완성합니다.

4. 핵심 자료구조: 스택과 큐 (Stack & Queue)

컴퓨터가 데이터를 어떤 순서로 쌓아두고 꺼낼 것인가를 결정하는 2대 기본 자료구조입니다.

  ■ 스택 (Stack: LIFO - 후입선출)
    ┌───────────────────────────┐
    │  입력 (PUSH) ➔            │  ▲ 출력 (POP : 맨 위에서 나옴)
    │  ┌─────────────────────┐  │  │
    │  │ 3. 데이터 C (최상단) │──┼──┘
    │  ├─────────────────────┤  │
    │  │ 2. 데이터 B         │  │
    │  ├─────────────────────┤  │
    │  │ 1. 데이터 A (최하단) │  │
    │  └─────────────────────┘  │
    └───────────────────────────┘
    * 프링글스 과자통: 나중에 넣은 데이터가 가장 먼저 나옴

  ■ 큐 (Queue: FIFO - 선입선출)
    [입구: Enqueue] ──➔ [ 데이터 C ] ──➔ [ 데이터 B ] ──➔ [ 데이터 A ] ──➔ [출구: Dequeue]
                        (가장 늦게 들어감)               (가장 먼저 나옴)
    * 터널 / 은행 번호표: 먼저 들어간 데이터가 가장 먼저 나옴

4.1 스택 (Stack: LIFO - Last In, First Out)

  • 특징: 바닥이 막힌 상자 구조로, 가장 나중에 들어간 데이터가 가장 먼저 나옵니다.
  • 핵심 연산: 데이터를 넣는 Push, 가장 위 데이터를 꺼내는 Pop.
  • 실생활 및 알고리즘 활용:
    • 웹 브라우저의 '뒤로 가기' 버튼
    • 문서 편집기의 '실행 취소(Ctrl+Z)'
    • ★ 수식의 괄호 짝 검사 (()()): 여는 괄호 (는 Push하고, 닫는 괄호 )가 나오면 Pop하여 짝이 맞는지 검사합니다.

4.2 큐 (Queue: FIFO - First In, First Out)

  • 특징: 양쪽이 뚫린 파이프 구조로, 가장 먼저 들어간 데이터가 가장 먼저 나옵니다.
  • 핵심 연산: 줄 맨 뒤에 데이터를 넣는 Enqueue, 맨 앞 데이터를 내보내는 Dequeue.
  • 실생활 활용: 은행 번호표 대기 순서, 프린터 인쇄 대기열, 너비 우선 탐색(BFS).

5. 재귀 함수와 콜스택 (Recursion & Call Stack)

5.1 재귀 함수(Recursive Function)의 개념

  • 함수가 종료되지 않고, 더 작은 크기의 문제를 해결하기 위해 자기 자신을 다시 호출하는 기법입니다.
  • ★ 필수 조건 (기저 조건, Base Case):
    재귀 호출을 멈추고 값을 반환하는 종료 조건이 없으면 컴퓨터 메모리가 터지는 스택 오버플로우(Stack Overflow)가 발생합니다.

5.2 팩토리얼(N!) 재귀 호출 추적

FUNCTION Factorial(N) {
    IF (N <= 1) {
        RETURN 1                     // 기저 조건 (종료 조건)
    } ELSE {
        RETURN N * Factorial(N - 1)  // 자기 자신을 N-1로 다시 호출
    }
}
  • 호출 및 반환 흐름 (Factorial(3) 실행 시):
    1. Factorial(3) 호출 ➔ 3×Factorial(2) 대기
    2. Factorial(2) 호출 ➔ 2×Factorial(1) 대기
    3. Factorial(1) 호출 ➔ 기저 조건 만족! 1 반환!
    4. 대기하던 값들이 역순으로 계산됨: 2×1=2 ➔ 3×2=6!

6. 알고리즘 효율성과 시간 복잡도 (Big-O Notation)

컴퓨터의 사양이 달라도 알고리즘 자체의 빠르기를 객관적으로 비교하기 위해, 입력 데이터의 개수 N이 증가할 때 연산 횟수가 증가하는 비율을 수학적으로 표기한 것이 빅오 표기법(Big-O)입니다.

6.1 빅오 서열 비교 (왼쪽이 압도적으로 빠름)

O(1)<O(logN)<O(N)<O(NlogN)<O(N2)<O(2N)
표기법 명칭 일상 비유 및 코드 패턴 데이터 100만 개일 때 계산 횟수
O(1) 상수 시간 사물함 번호 알고 바로 열기 (배열 인덱스 조회) 단 1번
O(logN) 로그 시간 스무고개 놀이, 이진 탐색 (Binary Search) 단 20번!
O(N) 선형 시간 1부터 N까지 차례로 훑기 (단일 1중 루프) 100만 번
O(N2) 제곱 시간 전교생끼리 서로 다 악수하기 (중첩 2중 루프, 버블 정렬) 1조 번 (컴퓨터 다운!)

6.2 이진 탐색 (Binary Search) 의 핵심 원리

  • 전제 조건: 반드시 데이터가 사전에 오름차순으로 정렬되어 있어야만 사용 가능!
  • 동작 원리: 중앙값을 확인하여 찾는 값이 왼쪽 또는 오른쪽에 있는지 판단 후, 매 단계마다 탐색 범위를 절반(1/2)씩 날려버립니다.
  • ★ 최대 비교 횟수 공식: 데이터가 N개일 때, 최대 비교 횟수는 log2​N을 올림한 정수값입니다.
    • N=64개 ➔ 26=64 이므로 최대 6번 만에 탐색 완료!
    • N=100만 개 ➔ 220≈104만이므로 단 20번 만에 탐색 완료!
