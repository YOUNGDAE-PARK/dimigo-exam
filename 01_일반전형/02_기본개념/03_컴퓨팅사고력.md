## 1. 순서도 (Flowchart) 읽기와 기호 판독

순서도(Flowchart)는 문제 해결의 절차(알고리즘)를 국제 표준 기호와 화살표로 시각화한 도면입니다.

```text
         [ 시작 (Start) ] ── (타원: 시작과 종료)
                │
                ▼
       [ X = 1, SUM = 0 ] ── (직사각형: 처리/연산/대입)
                │
                ▼
     ┌─＜ X <= 5 ? ＞────┐ ── (마름모: 조건 판단 갈림길)
     │       │ (Yes, 참)  │ (No, 거짓)
     │       ▼           ▼
     │ [ SUM = SUM + X ] [ PRINT(SUM) ] ── (평행사변형: 입출력)
     │ [ X = X + 1     ] │
     │       │           ▼
     └───────┘    [ 종료 (End) ]
```

### 💡 주요 표준 기호 총정리
* **타원 (Terminal)**: 프로그램의 **시작(Start)**과 **종료(End)**를 나타냅니다.
* **직사각형 (Process)**: 계산, 데이터 대입 등 실제 명령을 실행합니다 (`SUM = SUM + I`).
* **마름모 (Decision)**: 참(Yes) 또는 거짓(No)에 따라 실행 경로가 나뉘는 **조건 판단 분기점**입니다 (`I > 10?`).
* **평행사변형 (Data / I/O)**: 외부 입력을 받거나(`READ`), 최종 결과를 화면에 출력(`PRINT`)합니다.

## 2. 변수와 다중 제어 구조 상태 추적 (Tracing Algorithm)

알고리즘 문제의 90%는 머리가 아니라 **손**으로 풉니다. 코드가 한 줄씩 실행될 때마다 변수 안의 값이 어떻게 변하는지 빈 종이에 **변수 추적표(Trace Table)**를 그려가며 풀어야 실수를 원천 차단할 수 있습니다.

### 2.1 대입 연산자 (`=`) 와 SWAP 알고리즘
* 프로그래밍에서 `=`는 수학의 '같다'가 아니라, **"오른쪽 계산 결과를 왼쪽 변수 상자에 덮어쓰라"**는 명령입니다.
  * `X = X + 1` ➔ 현재 X에 1을 더한 값을 다시 X에 덮어씀 (X가 1 증가).
* **SWAP (값 맞바꾸기) 알고리즘**:
  두 변수 `A`와 `B`의 값을 맞바꿀 때는 반드시 임시 변수 `TEMP`가 필요합니다.
  ```text
  TEMP = A;   // 1. A의 기존 값을 TEMP에 임시 보관
  A = B;      // 2. B의 값을 A에 덮어씀
  B = TEMP;   // 3. 임시 보관해 둔 원래 A의 값을 B에 저장
  ```
  *(만약 TEMP 없이 A=B; B=A; 를 실행하면 A의 원래 값이 지워져 두 변수 모두 B의 값으로 같아지는 치명적 버그가 발생합니다.)*

### 2.2 중첩 반복문(Nested Loops) 실전 추적 훈련
실전 시험에는 반복문 안에 또 다른 반복문이 들어있는 **2중 중첩 반복문**이 단골로 출제됩니다.

**[추적 예제] 다음 코드가 종료된 후 화면에 출력되는 `CNT`의 값은?**
```text
CNT = 0
FOR (I = 1 to 3) {
    FOR (J = 1 to 2) {
        CNT = CNT + I * J
    }
}
PRINT(CNT)
```

**✅ 변수 추적표 (Trace Table)**:

| 외부 루프 `I` | 내부 루프 `J` | 연산 식 (`I * J`) | 누적 연산 (`CNT = CNT + I*J`) | 현재 `CNT` 값 |
|:---:|:---:|:---:|:---:|:---:|
| 시작 전 | - | - | - | **0** |
| **I = 1** | J = 1 | $1 \times 1 = 1$ | CNT = 0 + 1 | 1 |
| | J = 2 | $1 \times 2 = 2$ | CNT = 1 + 2 | **3** |
| **I = 2** | J = 1 | $2 \times 1 = 2$ | CNT = 3 + 2 | 5 |
| | J = 2 | $2 \times 2 = 4$ | CNT = 5 + 4 | **9** |
| **I = 3** | J = 1 | $3 \times 1 = 3$ | CNT = 9 + 3 | 12 |
| | J = 2 | $3 \times 2 = 6$ | CNT = 12 + 6 | **18** |

* **최종 출력**: `PRINT(CNT)` ➔ **`18`**

## 3. 블랙박스 함수 규칙 추론 (Function & Pattern)

내부 공식이 가려진 변환 상자(블랙박스 함수)에 숫자를 입력했을 때의 입출력 표를 분석하여, 숨겨진 함수 $f(x)$를 찾아내는 퍼즐입니다.

| 입력 ($x$) | 출력 ($y$) | 규칙 분석 (힌트 찾기) |
|:---:|:---:|:---|
| **2** | **7** | 2에 3배 하면 6 ➔ 1이 부족함 (+1) |
| **3** | **10** | 3에 3배 하면 9 ➔ 1이 부족함 (+1) |
| **5** | **16** | 5에 3배 하면 15 ➔ 1이 부족함 (+1) |
| **8** | **?** | $y = 3x + 1$ 규칙 성립! ➔ $3 \times 8 + 1 = \mathbf{25}$ |

* **규칙 도출 2단계 공식**:
  1. **기울기(변화율) 찾기**: $x$가 1 커질 때 $y$가 3씩 커지므로, 입력값에 **3을 곱하는 항($3x$)**이 기본입니다.
  2. **상수 보정하기**: $3 \times 2 = 6$인데 출력이 7이므로, 뒤에 **$+1$**을 더해 $f(x) = 3x + 1$을 완성합니다.

## 4. 핵심 자료구조: 스택과 큐 (Stack & Queue)

컴퓨터가 데이터를 어떤 순서로 쌓아두고 꺼낼 것인가를 결정하는 2대 기본 자료구조입니다.

```text
  ■ 스택 (Stack: LIFO - 후입선출)
    ┌───────────────────────────┐
    │  입력 (PUSH) ➔            │  ▲ 출력 (POP : 맨 위에서 나옴)
    │  ┌─────────────────────┐  │  │
    │  │ 3. 데이터 C (최상단) │──┼──┘
    │  ├─────────────────────┤  │
    │  │ 2. 데이터 B         │  │
    │  ├─────────────────────┤  │
    │  │ 1. 데이터 A (최하단) │  │
    │  └─────────────────────┘  │
    └───────────────────────────┘
    * 프링글스 과자통: 나중에 넣은 데이터가 가장 먼저 나옴

  ■ 큐 (Queue: FIFO - 선입선출)
    [입구: Enqueue] ──➔ [ 데이터 C ] ──➔ [ 데이터 B ] ──➔ [ 데이터 A ] ──➔ [출구: Dequeue]
                        (가장 늦게 들어감)               (가장 먼저 나옴)
    * 터널 / 은행 번호표: 먼저 들어간 데이터가 가장 먼저 나옴
```

### 4.1 스택 (Stack: LIFO - Last In, First Out)
* **특징**: 바닥이 막힌 상자 구조로, **가장 나중에 들어간 데이터가 가장 먼저 나옵니다**.
* **핵심 연산**: 데이터를 넣는 **`Push`**, 가장 위 데이터를 꺼내는 **`Pop`**.
* **실생활 및 알고리즘 활용**:
  * 웹 브라우저의 '뒤로 가기' 버튼
  * 문서 편집기의 '실행 취소(Ctrl+Z)'
  * **★ 수식의 괄호 짝 검사 `(()())`**: 여는 괄호 `(`는 Push하고, 닫는 괄호 `)`가 나오면 Pop하여 짝이 맞는지 검사합니다.

### 4.2 큐 (Queue: FIFO - First In, First Out)
* **특징**: 양쪽이 뚫린 파이프 구조로, **가장 먼저 들어간 데이터가 가장 먼저 나옵니다**.
* **핵심 연산**: 줄 맨 뒤에 데이터를 넣는 **`Enqueue`**, 맨 앞 데이터를 내보내는 **`Dequeue`**.
* **실생활 활용**: 은행 번호표 대기 순서, 프린터 인쇄 대기열, 너비 우선 탐색(BFS).

## 5. 재귀 함수와 콜스택 (Recursion & Call Stack)

### 5.1 재귀 함수(Recursive Function)의 개념
* 함수가 종료되지 않고, 더 작은 크기의 문제를 해결하기 위해 **자기 자신을 다시 호출**하는 기법입니다.
* **★ 필수 조건 (기저 조건, Base Case)**:
  재귀 호출을 멈추고 값을 반환하는 종료 조건이 없으면 컴퓨터 메모리가 터지는 **스택 오버플로우(Stack Overflow)**가 발생합니다.

### 5.2 팩토리얼($N!$) 재귀 호출 추적
```text
FUNCTION Factorial(N) {
    IF (N <= 1) {
        RETURN 1                     // 기저 조건 (종료 조건)
    } ELSE {
        RETURN N * Factorial(N - 1)  // 자기 자신을 N-1로 다시 호출
    }
}
```
* **호출 및 반환 흐름 (`Factorial(3)` 실행 시)**:
  1. `Factorial(3)` 호출 ➔ $3 \times \text{Factorial}(2)$ 대기
  2. `Factorial(2)` 호출 ➔ $2 \times \text{Factorial}(1)$ 대기
  3. `Factorial(1)` 호출 ➔ 기저 조건 만족! **`1`** 반환!
  4. 대기하던 값들이 역순으로 계산됨: $2 \times 1 = 2$ ➔ $3 \times 2 = \mathbf{6}$!

## 6. 알고리즘 효율성과 시간 복잡도 (Big-O Notation)

컴퓨터의 사양이 달라도 알고리즘 자체의 빠르기를 객관적으로 비교하기 위해, **입력 데이터의 개수 $N$이 증가할 때 연산 횟수가 증가하는 비율**을 수학적으로 표기한 것이 **빅오 표기법(Big-O)**입니다.

### 6.1 빅오 서열 비교 (왼쪽이 압도적으로 빠름)
$$O(1) < O(\log N) < O(N) < O(N \log N) < O(N^2) < O(2^N)$$

| 표기법 | 명칭 | 일상 비유 및 코드 패턴 | 데이터 100만 개일 때 계산 횟수 |
|:---:|:---:|:---|:---:|
| **$O(1)$** | 상수 시간 | 사물함 번호 알고 바로 열기 (배열 인덱스 조회) | 단 **1번** |
| **$O(\log N)$** | 로그 시간 | 스무고개 놀이, **이진 탐색 (Binary Search)** | 단 **20번**! |
| **$O(N)$** | 선형 시간 | 1부터 N까지 차례로 훑기 (단일 1중 루프) | **100만 번** |
| **$O(N^2)$** | 제곱 시간 | 전교생끼리 서로 다 악수하기 (중첩 2중 루프, 버블 정렬) | **1조 번** (컴퓨터 다운!) |

### 6.2 이진 탐색 (Binary Search) 의 핵심 원리
* **전제 조건**: **반드시 데이터가 사전에 오름차순으로 정렬**되어 있어야만 사용 가능!
* **동작 원리**: 중앙값을 확인하여 찾는 값이 왼쪽 또는 오른쪽에 있는지 판단 후, 매 단계마다 탐색 범위를 **절반($1/2$)씩 날려버립니다**.
* **★ 최대 비교 횟수 공식**: 데이터가 $N$개일 때, 최대 비교 횟수는 **$\log_2 N$을 올림한 정수값**입니다.
  * $N = 64$개 ➔ $2^6 = 64$ 이므로 최대 **6번** 만에 탐색 완료!
  * $N = 100$만 개 ➔ $2^{20} \approx 104$만이므로 단 **20번** 만에 탐색 완료!

## 7. 2D 바둑판 격자 로봇 시뮬레이션 (Grid Robot Simulation)

컴퓨팅 사고력 시험에서는 2차원 평면 좌표 위에서 로봇이나 캐릭터가 정해진 명령(앞으로 이동, 좌회전, 우회전 등)에 따라 이동할 때 최종 좌표나 경로를 묻는 문제가 빈출됩니다.

### 7.1 방향 벡터와 좌표 이동 규칙
* **기본 좌표 체계**:
  * 북쪽(위쪽)으로 1칸 이동: $Y$ 좌표 **$+1$** (남쪽으로 이동: $Y$ 좌표 **$-1$**)
  * 동쪽(오른쪽)으로 1칸 이동: $X$ 좌표 **$+1$** (서쪽으로 이동: $X$ 좌표 **$-1$**)
* **90도 회전 시 머리 방향의 변화**:
  * **우회전(R, 시계 방향)**: 북 ➔ 동 ➔ 남 ➔ 서 ➔ 북
  * **좌회전(L, 반시계 방향)**: 북 ➔ 서 ➔ 남 ➔ 동 ➔ 북

### 7.2 시험장 100% 득점 팁 (십자 방향키 그리기)
1. 머리로 회전 방향을 계산하면 좌회전과 우회전을 반대로 착각하기 쉽습니다.
2. 문제지 여백에 즉시 **`동서남북` 십자 방향키**를 작게 그려두세요.
3. 로봇이 회전할 때마다 **현재 바라보는 방향 화살표에 동그라미**를 치고, 전진할 때마다 해당 축의 숫자를 가감하면 절대 틀리지 않습니다.

### [문제 3: 이진 탐색 비교 횟수 계산]
1부터 128까지 크기 순서대로 정렬된 128개의 정수 데이터가 들어있는 배열이 있습니다. 이 배열에서 특정한 목표값(Key)을 찾기 위해 **이진 탐색(Binary Search)**을 수행할 때, 목표값을 찾거나 데이터가 없음을 확인할 때까지 거쳐야 하는 **최대 비교 횟수**는 몇 회입니까?

## 🎯 정답 및 단계별 풀이 해설

### [문제 1 정답] ③
* **풀이 해설 (Trace Table 작성)**:
  * 외부 루프 A는 1부터 4까지, 내부 루프 B는 1부터 A까지 돕니다.
  * `A=1`일 때:
    * B=1: (B!=2) ➔ TOTAL = 0 + 1 = **1**
  * `A=2`일 때:
    * B=1: TOTAL = 1 + 1 = 2
    * B=2: (B==2) ➔ TOTAL = 2 + 5 = **7**
  * `A=3`일 때:
    * B=1: TOTAL = 7 + 1 = 8
    * B=2: (B==2) ➔ TOTAL = 8 + 5 = 13
    * B=3: TOTAL = 13 + 1 = **14**
  * `A=4`일 때:
    * B=1: TOTAL = 14 + 1 = 15
    * B=2: (B==2) ➔ TOTAL = 15 + 5 = 20
    * B=3: TOTAL = 20 + 1 = 21
    * B=4: TOTAL = 21 + 1 = **22**
  * 루프 종료 후 출력값은 **`22`**입니다.

### [문제 2 정답] ③
* **풀이 해설 (스택 상태 추적)**:
  1. `PUSH(10)` ➔ 스택: `[10]`
  2. `PUSH(20)` ➔ 스택: `[10, 20]`
  3. `POP()` ➔ 가장 늦게 들어간 20이 빠져나옴 ➔ 스택: `[10]`
  4. `PUSH(30)` ➔ 스택: `[10, 30]`
  5. `PUSH(40)` ➔ 스택: `[10, 30, 40]`
  6. `POP()` ➔ 가장 늦게 들어간 40이 빠져나옴 ➔ 스택: `[10, 30]`
  7. `PUSH(50)` ➔ 스택: `[10, 30, 50]`
  * 최종 스택에 남아 있는 데이터는 **10, 30, 50**입니다.
  * 총합: $10 + 30 + 50 = \mathbf{90}$.

### [문제 3 정답] ①
* **풀이 해설**:
  * 이진 탐색은 매 비교마다 검색 대상 데이터의 범위를 절반($1/2$)으로 줄입니다.
  * 전체 데이터 개수가 $N = 128$일 때:
    * 1회 비교 후: 64개 남음
    * 2회 비교 후: 32개 남음
    * 3회 비교 후: 16개 남음
    * 4회 비교 후: 8개 남음
    * 5회 비교 후: 4개 남음
    * 6회 비교 후: 2개 남음
    * 7회 비교 후: 1개 남음 (탐색 종료)
  * 공식: $2^7 = 128$ 이므로, 최악의 경우 거쳐야 하는 최대 비교 횟수는 **$\mathbf{7}$회**입니다!

### [문제 4 정답] ②
* **풀이 해설 (방향 및 좌표 단계별 추적)**:
  * 시작: (0, 0), 방향: **북**
  * `F` ➔ (0, 1), 북
  * `F` ➔ (0, 2), 북
  * `R` ➔ 방향 우회전: **동** (좌표 변동 없음: (0, 2))
  * `F` ➔ (1, 2), 동
  * `F` ➔ (2, 2), 동
  * `F` ➔ (3, 2), 동
  * `R` ➔ 방향 우회전: **남** (좌표 변동 없음: (3, 2))
  * `F` ➔ (3, 1), 남 (남쪽이므로 Y좌표 1 감소)
  * `L` ➔ 남쪽에서 좌회전: **동** (좌표 변동 없음: (3, 1))
  * `F` ➔ (4, 1), 동 (동쪽이므로 X좌표 1 증가)
  * 따라서 로봇의 최종 위치는 **`(4, 1)`**입니다!
